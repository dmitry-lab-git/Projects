исторических сегментов:

  - Статус: Верифицирован. Конечный системный ID = 533.
  - Условие фильтрации: Строки со значением source_code >= 447 исключаются.

* ЭПОХА 2 (Операции 447 – 1269)
  - Источник: Таблица public.transaction_registry_flw_030_transform.
  - Статус: Обработан Python-движком, расхождения отсутствуют (delta = 0.00).
  - Точки инициализации сальдо: Системные ID 534 и 535 (правило INJECT_ROWS 
    для фиксации входящего баланса на момент закрытия операции 446).
  - Конечная точка: Системный ID = 1362.

* ЭПОХА 3 (Операции 1270+)
  - Источник: Таблицы public.tx_register и public.ledger.

3. СПЕЦИФИКАЦИЯ ЦЕЛЕВОЙ ТАБЛИЦЫ PUBLIC.GLOBAL_LEDGER
-------------------------------------------------------------------------------
Таблица аккумулирует трансформированные данные всех трех периодов. Схемы 
исходных таблиц (включая int4 для tr_sum в public.tx_register) приводятся 
к единому формату NUMERIC(15, 2).

Поля целевой таблицы:
* global_id       : BIGSERIAL PRIMARY KEY (Сквозной индекс)
* epoch_tag       : VARCHAR(15) (Маркеры сегментов: STAGE_1, STAGE_2, STAGE_3)
* source_tr_id    : INTEGER (Соответствует полю code из public.tx_register)
* op_date         : TIMESTAMP WITHOUT TIME ZONE (Дата транзакции)
* account_id      : VARCHAR(10) (Системный идентификатор счета ACC-XXX)
* tr_type         : VARCHAR(50) (Идентификатор типа операции)
* amount          : NUMERIC(15, 2) (Сумма операции с поддержкой копеек)
* running_balance : NUMERIC(15, 2) (Сквозной накопительный итог баланса)
* project         : VARCHAR(100) (Идентификатор проекта)
* category        : VARCHAR(100) (Идентификатор управленческой категории)
